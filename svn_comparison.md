# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто файл-указатель (41 байт) на конкретный коммит в
`.git/refs/heads/`. Создание ветки не копирует ни одного файла проекта и
занимает доли секунды, переключение меняет только изменившиеся файлы.
В SVN ветка — это копия директории (`svn copy trunk branches/feature`) на
центральном сервере. Операция идёт по сети, создаёт отдельную ревизию, а
слияние веток исторически было ручным и болезненным (до SVN 1.5 не было
даже merge-tracking). Поэтому в SVN ветки создают редко и надолго.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система: история и ревизии хранятся только на
сервере, а у разработчика лежит лишь рабочая копия последней версии.
`svn commit` — это сетевая операция, которая создаёт новую ревизию на
сервере. Офлайн можно только редактировать файлы и смотреть локальный
`svn diff`. В Git коммит — локальная операция, на сервер он попадает
позже через `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Большие бинарные файлы (игровые ассеты, CAD-модели, видео): не нужно
  выкачивать всю историю бинарников, можно взять только нужную ревизию.
- Необходимость блокировок файлов (`svn lock`) — для файлов, которые
  невозможно смержить (psd, docx, модели), чтобы двое не правили их одновременно.
- Жёсткий централизованный контроль доступа вплоть до отдельных каталогов
  (path-based authorization) — встречается в госсекторе и банках.
- Частичный checkout: можно выкачать только одну поддиректорию огромного
  монорепозитория.
- Legacy-проекты, где миграция истории на Git дороже, чем её польза.
